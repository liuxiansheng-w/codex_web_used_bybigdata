### Git 快捷提交与推送

入口位于左侧每个项目右侧常驻显示的「⋯」菜单，选择「Git 提交与推送」；顶部项目名称旁保留同一入口。左侧菜单操作所点击的项目，不切换当前聊天和编辑器，Git 说明与勾选也按项目隔离。弹窗左侧勾选文件，右侧查看相对 HEAD 的完整磁盘差异（不是未保存编辑草稿），底部填写说明并选择「仅提交」「提交并推送」或「仅推送已有提交」。重命名按删除＋新增显示，需要同时选择两项。未勾选的已暂存文件不会纳入提交；新文件在提交失败时可能留在暂存区，提示后需刷新核对。

推送使用当前分支已经配置的单一上游地址，明确显示目标及基于本地跟踪引用的待推送数量；包含此前尚未推送的提交，不自动 fetch、pull、强推或推送标签，不执行 hooks 或签名。未配置 upstream、游离 HEAD、冲突/合并中、首次提交和子目录项目会给出明确限制，需要先在本机 Git 客户端处理。隐藏、项目排除项、符号链接和特殊文件不进入可选列表；大于 1 MB 或非 UTF-8 新文件仅提示本机核对。不要选择凭据、缓存或个人文件。

状态版本变化时拒绝旧操作；重复请求使用同一操作标识核对。提交成功但推送失败会保留本地提交，使用「仅推送已有提交」重试。页面内按项目保留未提交的说明和勾选，刷新页面不持久化。测试只使用临时仓库和本机临时裸仓库，不触碰真实远程。后端接口升级需在生产任务全部空闲后通过现有 LaunchAgent 重启，不可中断活动任务。

在浏览器中使用本机 Codex 的中文工作台。输入任务后，可以查看流式回复、工具执行和文件修改，并处理 Codex 发起的审批与补充问题。

顶部可切换「对话 / 并排 / 文件」工作区；搜索、审查和设置以工具面板打开，不挤窄编辑区。普通执行记录按轮次归并，子任务的说明和回复直接可读；用户消息提供复制与编辑后重发，编辑只准备草稿。代码、Excel 和 PDF 使用同一组文件标签。完整改造说明见 [桌面体验评审与落实记录](PRODUCT-UX-REVIEW.md)。

## 启动

需要 Node.js 22.13+（22 LTS）或 24+，以及已安装并登录的 Codex。推荐 Node 24。优先使用 Cursor 的官方 Codex 扩展自带运行时；找不到时使用 PATH 上的 Codex CLI。SQL/Python 文本处理使用固定版本的 SQL Formatter 和 Ruff WASM（锁定于 package-lock.json）。

```sh
cd /Users/liuxiansheng/Desktop/dw_job/临时任务/data_request/刘正阳任务/AI/codex-web-shell
npm ci --ignore-scripts
PORT=4318 npm start
```

当前 Mac 打开 **https://ningmeng.com/**，也可使用 **http://127.0.0.1:4318/**。当前 4318 由用户级 LaunchAgent `com.local.ningmeng-workbench` 常驻管理，登录时启动，进程退出后自动恢复；不依赖维护终端或聊天任务存活。上面的命令仅用于手动运行，已有后台服务时不要重复启动同一端口。未指定 `PORT` 时，手动运行默认使用 4317。

后台配置位于 `~/Library/LaunchAgents/com.local.ningmeng-workbench.plist`，使用 `/usr/local/bin/node` 和本项目 `server.mjs`，默认工作目录为 `dw_job`。状态可用 `launchctl print gui/$(id -u)/com.local.ningmeng-workbench` 检查；运行日志位于 `~/Library/Logs/Ningmeng/workbench.stdout.log`、`~/Library/Logs/Ningmeng/workbench.stderr.log`（仅当前用户可读写）。LaunchAgent 的启动目录使用用户主目录，应用代码仍从本项目绝对路径加载，默认项目由 `WORKSPACE_CWD` 指定；避免 launchd 在启动进程前直接进入桌面目录或在其中创建日志。需要维护停机时使用 `launchctl bootout gui/$(id -u)/com.local.ningmeng-workbench`；恢复使用 `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.local.ningmeng-workbench.plist`。停止或重启前必须先确认无运行中会话、审批、终端和查询，不能直接 kill 进程充当正常停机。

如果没有登录，先执行 `codex login`，然后在页面点击「重新连接」。页面不接收、复制或保存 OpenAI API Key / ChatGPT 登录 Token。

实时推送首次加载完整历史，后续只传变化的消息；大历史或慢连接会合并等待中的状态，不因超过 8 MB 就主动断开。网络恢复或服务重启后页面自动重新同步，保留聊天输入、编辑草稿和打开的文件；恢复只读取状态，不自动重发消息、审批、SQL 或终端命令。

项目实体目录已迁至上面的 AI 目录；原 `/Users/liuxiansheng/Desktop/dw_job/codex-web-shell` 仅保留兼容符号链接，历史文件引用和已有启动入口仍可使用。迁移后默认工作目录仍为最外层 Git 仓库根目录 `dw_job`，不会因经过嵌套仓库而变化；可通过 `WORKSPACE_CWD` 显式指定。

可选配置：

```sh
PORT=4318 npm start
CODEX_BIN=/absolute/path/to/codex npm start
SQL_RUNNER_URL=http://127.0.0.1:5177 npm start
```

### 当前 Mac 的域名入口

当前使用的 4318 工作台配置了 **https://ningmeng.com/**，输入 `http://ningmeng.com/` 会自动跳转到 HTTPS。仅在这台 Mac 的 `/etc/hosts` 中解析为 `127.0.0.1`，不需要购买域名或配置公网 DNS。原来的 `http://127.0.0.1:4318/` 仍可使用；两个地址连接同一个工作台后端。

独立 Nginx 代理仅监听 `127.0.0.1:80` 和 `127.0.0.1:443`，配置与证书位于 `/Library/Application Support/Ningmeng/Domain/`，由 `/Library/LaunchDaemons/com.local.ningmeng-domain.plist` 随系统启动。代理不负责启动工作台；后端由当前用户的 `com.local.ningmeng-workbench` LaunchAgent 运行在 4318。系统进程负责绑定标准端口，请求工作进程以 `nobody` 身份运行，不修改已有 Nginx 主配置。Host、Origin、会话和 CSRF 校验保持生效，SSE 不缓存。

本机证书在当前用户登录钥匙串中受信任，仅用于 SSL 连接，证书 SAN 限定为 `ningmeng.com`，CA 标记为 false；不安装通用根 CA。证书有效期至 **2027-09-17**；到期前需要重新生成、安装并信任新证书。私钥和安装暂存文件只放在被 Git 忽略的 `.local/` 或系统运行目录，不能提交到仓库。

地址改变后，浏览器会将界面偏好、置顶和本机草稿视为独立存储；原地址的数据仍保留在那里，会话历史仍来自同一后端。切换前请先保存未完成的编辑。

维护文件：`scripts/local-domain-config.mjs` 生成代理配置；`scripts/install-local-domain.sh` 安装已准备好的 `.local/domain-staging/` 文件，需要管理员权限（macOS 桌面目录隐私限制下，先复制脚本及暂存文件到临时目录）。证书信任须以当前登录用户运行 `security add-trusted-cert -r trustRoot -p ssl -k "$HOME/Library/Keychains/login.keychain-db" "/Library/Application Support/Ningmeng/Domain/ningmeng.pem"`，在系统弹窗中授权。`node scripts/check-local-domain.mjs` 验证证书、跳转、会话、请求来源校验和流式连接，只读取数据并进行静态文本格式化，不调用模型或执行 SQL。

### 切换到 Cosmos

点击左下角「模型服务」，选择 Cosmos，首次填写自己的 Key 和应用类型，然后点击「验证并切换」。新配置默认选 Chatflow，服务地址为用户指定的 `http://cosmos-api-inner.qingsonghealth.net/v1`；已保存配置的类型、地址和 Key 保持不变。「高级设置」可修改地址、输入/输出变量，Responses 接口需要填写模型 ID。已有 Key 显示「已保存 · 自动沿用」，无需重复输入；点击「更换 Key」才展开输入框，新 Key 验证成功后才替换，取消更换清除草稿并继续沿用原 Key。更改服务地址时需填写对应地址的 Key。切回 Codex 无需重新登录。

- **Chatflow（对话流）**：应用标注 CHATFLOW，以「直接回复」结束。使用 `/chat-messages`，发送 `query` 和自定义 `inputs`，自动读取 `answer`，无需输出变量。开始节点的输入变量为 `input` 时保持默认；只有 `sys.query` 而无自定义变量时将输入变量留空。LLM 的用户提示词应引用开始节点的输入变量或 `sys.query`，直接回复引用 `LLM.text`，修改后重新发布。输入变量建议使用段落文本并调大最大长度，以容纳代码和工具上下文。
- **Workflow（工作流）**：应用标注 WORKFLOW，以「结束」输出变量。使用 `/workflows/run`，输入/输出变量必须与应用配置一致。
- Chatflow 使用 SSE 接收回复，兼容返回完整 JSON 的服务；必须收到 `message_end` 才会转换工具协议。取消时根据当前请求的 `task_id` 尝试停止生成，不重试推理。完整历史和工具结果每轮由本机运行时传入，不重复使用 Cosmos 的远端 `conversation_id`，避免不同会话或辅助请求串话；关闭 Cosmos 自动生成标题。

工作流接入通过文本工具协议适配到本机 Codex 运行时，先用两轮虚构内容验证工具调用与结果续答。只返回 SQL 或固定模板的工作流可能无法通过，需要让工作流完整传入提示词并原样输出模型结果；也可使用兼容的 Responses 模型接口。验证通过代表基础协议可用，不保证模型质量、多模态、云端插件或所有原生能力相同。运行时继续负责本机工具、Skill、权限和审批，适配层不直接执行命令。

模型回复中的自称不能用于判断服务路由。Cosmos 请求会补充身份说明：助手名称为「柠檬」，模型服务是 Cosmos，Codex 是本机工具宿主；保留原有工具/权限规则，不修改已有回复。Chatflow/Workflow 的底层模型取决于 Cosmos 的 LLM 节点，页面中的 `cosmos-chatflow` 只是接入别名，不能据此判断 Claude 或 GPT 的具体型号。

普通聊天先只发送实际对话和精简身份说明，不预先发送工具目录、Skill 清单、项目规则及本机环境。模型需要本机或项目能力时，通过 `load_context: "workspace"` 请求加载原有上下文，之后才能调用工具；同一轮的工具续答直接携带这些规则。精简仅替换精确识别的运行时默认说明，自定义提示词、未知说明和实际聊天保留，不用关键词硬编码闲聊回复，也不额外调用分类模型。普通文字回复可直接显示；工具和上下文请求仍须遵循 JSON 协议，不完整 SSE 不会当作成功。

加载本机上下文后，大工具集提供简短目录，需要时再加载所选工具的完整说明与参数；最近调用的四种工具直接携带完整定义。上下文首次加载增加一次模型请求，工具说明发现最多再增加两次，每次最多八个工具，不改变原有执行权限和审批。强制工具选择、结构化输出及 Responses 接入保留原协议。Cosmos 会话标题直接取首条消息的干净预览，不额外调用模型。聊天记录和工具结果仍占用上下文；缓存是否命中及实际 token 费用以 Cosmos 后台为准。

切换会进入新对话，旧对话和运行任务保留原模型；AI 续写跟随输入区显示的模型。Key 仅保存于本机忽略目录 `.local/model-provider/connection.json`，文件权限为 0600，不写入聊天、浏览器存储或日志。配置失败保留原 Key，不自动回退到 Codex。首次验证会调用所填 Key 对应的服务，不发送项目数据。

## 使用

- 左侧为可收起的项目文件栏，中间编辑文件，右侧集中显示会话列表、聊天与新建入口。聊天顶部返回箭头在列表和当前对话间切换，搜索与新建均在右上角；切换保留草稿、阅读位置和运行任务。输入区左侧是「＋」与权限，右侧是模型、推理强度和发送/停止。深色石墨底色搭配低饱和青色焦点，不使用大幅装饰或功能卡片占据对话空间。
- 输入任务，Enter 发送；Shift + Enter 换行。中文输入法选字时不会误发送。
- 每条用户消息和 AI 回复显示时间，当天显示时分，跨天带日期，悬停查看完整时间及来源。AI 每轮最后一条回复前显示总耗时，运行时实时更新，停止后固定；耗时包含工具执行和等待确认。优先使用原生时间，历史逐条时间从对应本机会话日志中按消息编号恢复（只读、64 MB 上限，不向页面返回原始日志）。没有逐条时间时仅对首条用户消息/最后回复使用本轮开始/结束时间并标明来源，其他缺失项显示「时间未记录」。断线不继续假计时，也不使用页面加载时间补造历史时间。
- ⌘/Ctrl + / 搜索会话；顶栏键盘按钮可查看快捷操作。用户消息气泡按内容宽度靠右显示，保留底部时间，不再撑满整行或重复显示「你」。长对话提供「回到最新消息」，阅读历史时新回复不抢滚动位置。每条 Codex 回复支持复制。
- 切换会话时保留本页内的未发送文字、附件、工具、计划和目标草稿；不同目录与会话隔离。首次输入时可选择是否开启本机草稿恢复，输入区持续显示保存方式，未发送文字/附件与未保存编辑均有刷新退出提醒。默认不持久化；「设置 → 常规与草稿」可开启、恢复或清除本机缓存，启动时提示可恢复的编辑草稿。附件 ID、工具选择、目标及完全访问授权不写入持久草稿，重启后需重新添加附件。
- 会话标题保留原生已有名称；未命名的新会话与打开的历史会话先显示最多 28 字的干净预览。Cosmos 直接使用这段本机预览作为标题，不产生标题模型调用；Codex 继续依据首条消息生成简短概括，标题辅助轮次临时、只读、禁用工具，不出现在正常聊天或持久历史中。两者均移除自动生成的附件路径说明，并同步到原生 `thread.name`。手动名称及其他客户端较新的改名优先；标题生成失败不影响正常任务。收到名称更新、任务结束、打开会话或切回网页时同步，旧读取结果不覆盖新名称。
- 右侧会话列表按工作目录显示最近会话，默认紧凑显示标题、更新时间与日期分组，内容搜索时补充摘要；标题搜索查询原生服务端，选择「消息内容」可分页搜索当前项目对话正文（每页 40 个，只读，部分读取失败会明确提示）。支持归档筛选、重命名、归档/恢复、只读分支和整理上下文。置顶仅在本浏览器保存，明确标注；新建对话快捷键为 ⌘/Ctrl + K。
- 聊天区顶部显著显示当前对话名称；点击可查看完整名称、重命名或管理会话。右侧列表「进行中的会话」跨项目显示本服务已同步的运行、待确认/待回复和排队任务，与左侧文件树独立显示；最近会话同步显示状态，实时状态优先于旧历史列表。未打开的历史记录显示「未同步」，断线显示「待核实」，不推断其他客户端尚未同步的任务已经结束。
- 文件默认与聊天左右平铺，拖动中间分隔线调宽，双击重置；聚焦分隔线后可用方向键微调、Shift 加速、Home/End 到边界、Enter 重置，拖动时 Escape 取消。编辑器标题栏「浮动窗口／平铺页面」随时切换；浮动模式保留拖动、八方向缩放和最大化。记住手动选择的布局及平铺比例，切换不重建文本区、不丢草稿或撤销历史。可用宽度不足时自动上下平铺，分隔线改为调高度。
- 左侧栏右边界支持左右拖动，宽度自动保存在本机浏览器；双击边界恢复默认。聚焦边界后，左右方向键微调、Shift 加速、Home/End 调到边界、Enter 重置，拖动中按 Esc 取消。收起再展开保留宽度，窗口变窄时自动为工作区留出空间，不重建文件树或清空编辑草稿。
- 左侧始终显示当前项目文件树，按需展开目录；会话入口集中在右侧。支持刷新、收起全部；输入文件名即搜索整个项目，无需先展开目录。文件名搜索分批遍历，不再在 4,000 项或单目录 10,000 项处停止；匹配较少时自动继续查找，匹配较多时每页显示 200 项，翻页从上次进度继续。切换项目或搜索词立即取消旧请求，无法读取的目录会明确提示。
- 右上角外观按钮提供六套缩略预览：极光、深空、绯霞、曜石、辉光、经典，均可切换深浅色；点击立即生效，自动记住本浏览器的选择。设置中的外观选项同步。侧栏、聊天、弹窗、工作台、编辑器与 SQL/Python 高亮一同适配；切换不刷新页面，不影响未保存编辑、查询结果或会话权限。
- 左侧「项目」右侧的「＋」可新增本机项目：浏览文件夹或输入绝对路径，点击「添加并打开项目」。项目列表在本浏览器保留；单击项目即可切换。路径会先校验并解析真实目录，添加不复制、不上传项目文件，也不调用模型；Codex 离线时仍可切换项目并手动编辑文件。
- 切换项目保留本页内各自的文件标签、未保存修改、光标、滚动位置、对话输入和最近选中的会话。编辑器只显示当前项目标签；侧栏提示各项目未保存文件数。切换不会保存或丢弃草稿，也不会继承完全访问确认。项目行「×」只移除列表入口，不删除文件；当前项目需先切换再移除。
- AI 回复中的文件引用可直接点击，在当前编辑器打开并定位对应行；支持带尖括号的完整路径、中文、空格、括号以及 `:行号` / `#L行号`。点击已有文件标签时保留未保存编辑，不自动执行查询。

- 目标使用原生 thread goal 接口，支持可选 Token 预算、状态展示、暂停、恢复和移除。新会话目标随第一条消息保存；停止正在运行的任务也会暂停其活动目标。
- 输入框的权限按钮包含「请求批准」「帮我批准」「完全访问权限」，以及单独保留的「只读模式」。默认请求批准：工作目录内常规操作直接进行，跨权限边界由 Codex 请求批准，不代表每一次修改都会弹窗。
- 「帮我批准」使用官方自动风险审查，不在网页端自动同意请求；审查理由会作为执行记录显示。它不等于完全访问权限，也不保证所有高风险操作都会弹窗：运行时可能直接拒绝并要求寻找安全替代路径。
- 「完全访问权限」必须勾选风险确认并点击启用，发送时后端也校验确认标记。确认只保留在当前页面的当前会话，不写入全局配置或浏览器持久化存储。刷新、切换或新建会话后重置为请求批准；已完成的文件修改不会因此撤销。
- 「只读模式」使用 read-only + never。计划模式优先于审批选项，强制只读并禁止提权。组织策略限制的选项禁用；查询组织策略失败时，不开放新增的自动审查或完全访问选项。运行时仍会最终执行组织策略和工具自身的控制。
- 审批区提供「全部允许一次（数量）」与每条请求的「允许这一次 / 拒绝」。一键审批只包含点击时当前会话已列出的命令和文件修改，逐项提交并显示进度；新出现的请求不会自动加入，切换会话或断线停止剩余提交，失败保留在原卡片供手动处理。补充问题、插件表单/授权及权限扩展保持单独处理，已有表单输入不会被其他审批更新清空。权限扩展按钮明确标注「允许本轮权限」，不写入永久授权。
- 执行过程中点击「停止」中断任务。关闭网页不会终止后端任务；重新打开或刷新页面可恢复状态。停止后已经完成的文件修改不会自动撤销。

## 工作方式与范围

浏览器通过同源 HTTP + SSE 访问本地 Node 服务，Node 使用 `codex app-server --stdio` 双向 JSON-RPC。它接入与 Cursor 扩展同类的 Codex 后端接口；不修改或遥控 Cursor 扩展 UI，也不需要 Cursor 保持打开。

本机 Codex 管理登录、项目指令、配置和会话/目标持久化。浏览器保存目录、模型、会话编号、置顶、常用项目及界面偏好；显式开启后才将输入文字和编辑草稿以明文存入 localStorage（可清除，不适合共享设备）。编辑草稿恢复保留旧版本号，磁盘变化时仍触发冲突，绝不自动覆盖。页面刷新后同一服务内任务、审批和消息队列重新同步；队列只在服务内存中，服务重启不自动续发。

上传的附件存入系统临时目录下的独立 `codex-desk-attachments-*` 目录，文件权限为 0600，使用随机文件名，不覆盖原文件。每次服务会话总上传容量上限 100 MB、最多登记 200 项。历史消息可能引用这些临时文件，因此服务退出不立即删除它们；系统清理临时目录后，继续处理历史附件可能需要重新添加。

浏览器通过 `127.0.0.1`/`localhost` 或上述仅本机可用的 `ningmeng.com` 入口访问；服务校验 Host、Origin、HttpOnly 会话和 CSRF 标记，不启用跨域，不提供任意文件读取接口。适用于本人在可信本机使用，不是多用户或公网服务。

当前增强菜单验证基线：Cursor 扩展 **26.908.31457** 自带 Codex **0.154.0-alpha.6.1**，Node.js **24.14.1**；基础聊天曾在独立 CLI **0.148.0** 验证。App Server 仍在演进，升级后建议重新验证。

这不是官方客户端的一比一复刻。依照用户选择，录制技能、原生电脑/浏览器控制、原生语音和屏幕上下文等桌面能力明确标注「网页暂不支持」，使用本机已注册的 `codex://` 唤起入口；没有偷偷添加系统桥接或授予系统权限。未支持的 MCP 模式（如设备验证）明确拒绝并提示官方客户端。

## 项目工作台

顶部「终端」打开工作区底部面板，与「查询结果」共用 Tab 栏。可拖动上边缘调整高度、展开/还原或收起；收起后保留 Tab 栏，点击恢复，刷新记住面板状态和高度。Tab 切换保留输出、命令草稿、结果标签及筛选，不停止后台任务；查询完成不抢走正在看的终端。查询结果仍可独立浮动，也可放回下方；关闭编辑器后仍可查看本项目结果。搜索、变更、成果和设置继续使用工具抽屉，会话管理从会话标题和列表菜单进入。

任务结束后直接呈现回复正文，不追加命令数量、异常推断或验收汇总卡片。需要检查文件时，打开顶部「变更与审查」查看本轮记录的差异及工作区变更，或打开「本轮成果」预览相关文件；普通命令/搜索按轮次合为一份可展开的执行过程，错误和进度在摘要中标记，详细输出仍保留。会话是否失败、停止或断线仍按实际会话状态显示。成果列表只提取当前轮次的文件记录和项目内 Markdown 链接，打开时读取磁盘版本，不保证链接所指文件仍存在。

执行中默认展开过程，展示运行时提供的公开工作摘要、逐项任务计划和工具进度；手动收起后不会被更新重新展开。命令优先用原生解析出的读取/搜索等动作作为标题，展开可看完整命令、目录、输出、退出码和原生耗时；网页动作区分搜索、打开与页内查找。原始思考和工具参数不会传入页面，不额外调用模型。历史只能恢复运行时实际留存的信息，计划更新及 MCP 进度在当前服务观测后保留，不为旧会话编造步骤。

### 文件恢复、文档预览与 AI 子任务

- 文件修改记录下点击「查看差异 / 回退」，差异直接展开，点击「撤销这次改动…」先预览回退，核对差异再确认。新建文件撤销时移入系统废纸篓；删除记录仅在目标路径仍为空闲时恢复。记录不完整、位置不匹配、重命名、项目中有运行任务或审批时不自动恢复。
- 编辑器「更多 → 修改历史 / 回退」提供网页保存历史。旧版本持久化到 `.local/file-history.json`（本机明文，0600）；每文件 20 份、总计 100 份 / 24 MB，自动滚动保留。首次启用之前的编辑器保存没有历史；外部工具的改动需有 AI 差异记录。恢复本身也保留原有磁盘版本。预览有效期五分钟，应用时再次检查版本；未保存草稿会阻止恢复。
- 点击 `AIdata` 中明确引用的 Excel 导出文件可直接预览（xlsx/xls/xlsm）；该目录仍不参与自动文件树扫描或项目搜索，不开放文本编辑和任意隐藏路径访问。
- 文件树直接点击 PDF/Excel 即可预览；与代码共享文件标签，切换保留页码、工作表、筛选和阅读位置，关闭标签/重新读取才释放预览资源。PDF 支持文字选择和整份文档查找；Excel 第一行默认显示为表头，不计入数据；支持与 SQL 结果一致的去重值勾选/数量、搜索、全选/反选、条件筛选、排序和 50/100/200 行分页，可复制行/列/表头/整表及导出筛选 CSV。拖选或 Shift 扩选单元格后，底栏显示计数、数值个数、求和、平均值、最大值和最小值，支持 Ctrl/⌘+C 和 Esc。筛选及复制覆盖所有已加载页，统计仅针对当前页；截断范围始终标注，下载原文件保留完整内容。打开的文档自动检查磁盘版本，选中文字时延后替换。解析库与字体均由本机服务提供，无外部文件上传。单文件上限 10 MB；Excel 在有限内存、10 秒时限的独立 worker 中解析，压缩工作簿展开上限 32 MB。
- 子任务的任务说明、实际状态和最新回复直接显示在主对话；同一轮重复的协作事件合并，回复按 Markdown 展示，不折叠。顶部「AI 子任务」提供集中查看入口，完整会话用于进一步查看执行细节，进入后可从顶部返回主任务；支持单独停止运行中的子任务。活动任务每 2.5 秒同步，已结束任务每 15 秒同步，页面隐藏时暂停；关闭侧栏不影响主对话更新。刷新保留卡片、焦点和选中文字。最多读取 40 个、8 层；回复预览上限 5,000 字符并明确提示。读不到状态会标为未同步，保留上次内容，不推断成功，不自动创建子任务。
- 这一轮未接入元数据接口，原有 SQL AI 续写保持原来的有限文件上下文。
